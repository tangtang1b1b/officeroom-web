# 工作方式

## 分工(以省 token 為優先)
- 主對話 = 協調者:討論、規劃、分派、整合。實作依「規劃書」標好的難度派給工人:
  易 → `bulk-worker`(haiku)、中 → `api-dev`(sonnet)、難 → `hard-dev`(opus);高風險改動最後送 `reviewer`(opus)。
- 要執行規劃書:使用 `dispatch` skill(說「執行規劃書」即可)。討論完要整理規劃書:使用 `write-plan` skill(說「寫規劃書」)。
- 難度在「規劃時」就標好,分派時照標記做,不要重新判斷;沒標的往上一級派。
- 自己動手的例外:單檔小修;互相牽連、派出去要重交代大量背景的改動。自己做之前先用一句話說明原因。
- 跑測試:直接 `<測試指令> 2>&1 | tail -15`,不派工;輸出很長才派工。
- 搜尋範圍超過 3 個檔案 → 用 Explore agent,只要結論。
- 派工前先用一句話說明「派給誰、做什麼」;結束時列出各工人完成了什麼。
- subagent 只回簡短摘要(改了哪些檔、關鍵決定、注意事項),不貼完整程式碼。
- 一個功能完成並 commit 後,建議開新對話(長對話每一輪都要重讀前文,最耗 token)。

## 專案指令(換專案時改這裡)

- 規劃書放:`docs/plans/`
