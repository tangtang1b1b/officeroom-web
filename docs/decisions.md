# 決策紀錄

## 2026-11-06：在現有 Nuxt 3 專案內建置遊戲

- 決策：沿用 Nuxt 3，將 Three.js 場景放入 client-only 元件；遊戲狀態、情境事件與畫面渲染分開。
- 原因：工作區已有 Nuxt 3 starter；計劃亦允許既有團隊沿用 Nuxt，Three.js 在 client-side 掛載與清理。
- 影響：保留既有 Nuxt 結構與全域樣式，新增 Three.js 依賴及遊戲頁面程式。
- 取代：無。

## 2026-11-06：先用程序生成場景資產

- 決策：第一版以程序生成幾何作為道路、車輛、護欄、植被及駕駛前景，並使用一張本地 CC0 道路紋理；只在模型可下載、授權與效能確認後替換占位車輛。
- 原因：計劃要求先讓核心玩法可玩；Sketchfab 車輛頁回覆 403，Quaternius Cars Pack 的下載頁連線中斷，未取得可核實的模型檔案。
- 影響：道路貼圖可追溯至 Poly Haven；車輛仍使用占位幾何，待來源可用後再評估導入。
- 取代：無。

## 2026-11-06：加入實際軌跡回顧與碰撞演出

- 決策：沿用既有 Three.js 程序場景；以固定步長軌跡供外部視角重播，碰撞先播放短演出後才顯示結算。對向車改為連續沿道路移動，事件可見時刻由簡化道路視線遮蔽估算。
- 原因：核准需求要求回看實際騎乘、呈現碰撞過程，並避免以倒數計時假裝道路遮蔽。
- 影響：`useRoadSafetyGame.js` 記錄軌跡與演出狀態，`RoadScene.client.vue` 依狀態渲染騎乘及回放畫面。
- 取代：擴充 2026-11-06「先用程序生成場景資產」決策；候選模型匯入仍需先取得可核實授權與檔案，本次未取得外部車輛／植物模型。

## 2026-11-06：匯入已核實授權的機車模型

- 決策：將 Tahseen 的 Motorcycle GLB 用於外部視角重播，保留模型授權檔與作者標示。
- 原因：使用者核准使用已討論的機車模型；Brave 既有登入工作階段可下載，套件內授權為 CC BY 4.0，GLB 約 3 MB、1K 貼圖、58,135 triangles。
- 影響：模型位於 `public/models/motorcycle/`，由 Three.js GLTFLoader 載入；僅外部重播顯示，第一人稱操作與現有座艙保留。
- 取代：修訂前一項重播決策中「尚未取得外部機車模型」的狀態；其他車輛及環境素材仍依原資產規則核實後再匯入。


## 2026-11-06：使用已授權的卡車模型替換車輛幾何

- 決策：將 F707 的 Mitsubishi Fuso Ecanter 用作前車、ElectroNick 的 Dump Truck 用作對向車；GLTFLoader 載入後依模型包圍盒正規化長度與落地位置。
- 原因：使用者要求以 Brave 直接下載已討論的模型；Sketchfab 頁面標示 CC BY 4.0，Dump Truck 套件含授權檔。Fuso 1K 下載未完成，採用同一模型已下載的 4K GLB。
- 影響：新增模型檔至 `public/models/box-truck/` 和 `public/models/oncoming-truck/`，並於 `RoadScene.client.vue` 載入，成功載入後替換程序幾何；授權與來源登記在 `CREDITS.md`。
- 取代：修訂「先用程序生成場景資產」中前車與對向箱型車採程序幾何的決定；其他環境程序幾何不變。

## 2026-11-06：加入盲彎前的等待或超車決策

- 決策：盲彎前暫停顯示當下路況因素，玩家可等待或評估超車；只有估計可用會車時間大於超車需求時才允許選擇超車。前車減速維持低速，車流通過且玩家回到原車道後結束短情境。
- 原因：使用者回報原玩法沒有可操作選擇、無操作也可能追撞，且車輛通過後路段仍無限延伸。
- 影響：`useRoadSafetyGame.js` 控制決策狀態、事件結果與情境結束；`pages/index.vue` 呈現選項與路況因素；`RoadScene.client.vue` 更新第一人稱車輛、側傾及通過後隱藏車輛。
- 取代：取代原先以約 1.1 公里道路作為完整體驗長度的規格；模型原本僅供外部重播的呈現限制也由第一人稱模型取代。

## 2026-11-06：依騎士視點配置機車與累積傾角

- 決策：機車模型以約 2.15m 車長維持實際場景尺度，修正模型朝向並與騎士視點共用位置 rig；相機掛在 rig 的騎士眼點，車體與視角依輸入逐步累積傾斜，放開後平順回正。
- 原因：使用者指出模型方向、第一人稱視點及模型比例都不正確，轉向傾斜也必須隨輸入逐步建立。
- 影響：`RoadScene.client.vue` 將機車設為約 2.15m，卡車維持約 4.8m；第一人稱鏡頭位於車身上方，模型前整流罩、把手和油箱顯示在視野下方，回放仍採外部鏡頭並避開彎道山壁遮擋。
- 取代：取代第一人稱將整台機車縮放至 0.42 倍並放在相機前方的實作；亦明確修訂先前以單幀固定輸入計算傾角的方式。

## 2026-11-06：以座艙與車道比例加強第一人稱空間感

- 決策：第一人稱呈現既有模型提供的風鏡、儀表和油箱；維持前車與車道線在中央視野，車款細節可與參考圖不同。左轉時機車本體與視野向左傾，右轉時兩者向右傾。
- 原因：使用者提供兩張騎乘視角參考，指定直行座艙構圖與傾斜方向，並要求保留切換車道時的空間不確定感。
- 影響：`RoadScene.client.vue` 使用現有機車模型呈現座艙，並同步傾斜車身與相機；不補造模型沒有的零件，也不更換機車資產或模仿指定車款細節。
- 取代：補充「依騎士視點配置機車與累積傾角」決策的座艙構圖與左右轉向視覺驗收條件；後續修正明確取消補造後照鏡。

## 2026-11-06：不補造現有模型沒有的後照鏡

- 決策：後照鏡僅在機車原始模型本身提供時顯示；不以程序幾何代替。左右輸入仍控制切道及傾斜，但橫移速度與範圍保持在道路內，避免相機快速偏到路肩。
- 原因：使用者指出原始機車沒有相符後照鏡，補造鏡體不符合要求；右轉測試亦顯示相機橫移至路肩後被山壁遮擋。
- 影響：移除 `RoadScene.client.vue` 的自製鏡體；`useRoadSafetyGame.js` 的左右移動速度改為 2.4m/s，位置範圍限制為 ±3.2m。
- 取代：取代「以座艙與車道比例加強第一人稱空間感」中以程序鏡體補足後照鏡的部分；其餘視角和傾斜要求仍有效。

## 2026-11-06：分開機車傾斜與視角轉向

- 決策：以未受車頭朝向旋轉的獨立 pivot 讓整台機車本體朝轉向側傾斜；相機只依輸入微幅左右轉向，保持地平線穩定。左輸入使車身左傾、視角左看；右輸入使車身右傾、視角右看。
- 原因：原本車身傾斜與模型朝向共用同一旋轉組，且相機使用相同角度翻滾，沒有清楚呈現本體傾斜和小幅視線轉向的分工。
- 影響：`RoadScene.client.vue` 把模型朝向與傾斜拆成巢狀群組，並以平滑 yaw 對應轉向輸入；取消相機跟隨車身角度翻滾。
- 取代：取代「依騎士視點配置機車與累積傾角」中讓相機與車身以同角度側翻的呈現方式；車身累積傾角與模型比例維持。

## 2026-11-06：校正對向卡車車頭朝向

- 決策：對向車模型車頭必須朝向玩家；載入模型時補上反向 heading，避免模型以車尾朝玩家倒車接近。
- 原因：使用者指出回放中對向卡車像倒車接近。
- 影響：`RoadScene.client.vue` 對對向車模型額外旋轉 180 度；沿用既有卡車資產與尺度。


## 2026-11-11：改做多人 3D 辦公室，部署於 Cloudflare

- 決策：第一人稱視角；被打中只留漆彈斑點；前端 `nuxt generate` 靜態輸出，與 Durable Object 遊戲伺服器同部署於 Cloudflare Worker；不使用 Colyseus，自寫房間邏輯；Durable Object 採一般 WebSocket accept 與 SQLite 型 migration。
- 原因：10 人規模、需免費且使用者操作最少；伺服器權威判定命中以防作弊。
- 影響：機車遊戲全部移除；格局資料與射線檢測放 `shared/` 供前後端共用。
- 取代：2026-11-06 的機車遊戲相關決策。

## 2026-11-11：簡化版物理由伺服器權威模擬

- 決策：可動物件限椅子與紙箱；桌子、隔板、螢幕固定。不引入物理引擎，自寫俯視 2D 圓形剛體；物件位置由 Durable Object 每 50ms 模擬並廣播(只送醒著或剛變動者)；前端只渲染不預測，也不把動態物件當障礙(玩家推動由伺服器處理，推不動時才 `correct`)。椅子重擊倒下 15 秒後自動扶正，紙箱只滑動。
- 原因：10 人規模、免費方案限制、需避免各端椅子位置不一致；完整物理引擎(如 Rapier)對這個規模過重，且 Worker 運算時間未驗證。
- 影響：伺服器每 tick 多一次物件模擬；`welcome` 與 `snapshot` 新增 `objects`，`paint` 新增 `objectId`；固定碰撞 `COLLIDERS` 不再含椅子與紙箱。
- 取代：先前「場景全為靜態碰撞方塊」的做法。

## 2026-11-14：椅子與螢幕可被射走(物理版)

- 決策：辦公桌的辦公椅(`CHAIRS` 內，如 `chair-will`)與每張桌子的螢幕(碰撞盒 id `${desk.id}-monitor`)可被漆彈槍射走，並由伺服器模擬真實物理。椅子獲得順射線方向的水平初速與旋轉，在地板上受摩擦減速，撞到牆、桌子、家具會被擋住或彈開，停下時呈倒下狀態；螢幕從桌面高度向射線方向飛出，受重力掉到地上，落地後滑一小段，停下時躺在地上。物品停下後留在原地當障礙：玩家不能穿過、也推不動；移動中的物品碰到玩家就停住，不推人。被射走的物品可再被射，再射會再給一次衝量並重新計算回復倒數。回復時間椅子 20 秒、螢幕 30 秒，從最後一次被射算起，集中於常數。回復時物品回到原位，原位有人就推開玩家(沿用 `pushPlayersOutOfProps`，以 CORRECT 同步，依回復前的碰撞盒計算)。有人坐著的椅子射不走(含離線同事人偶)。座位主人上線或離線、玩家坐下時，該座位的椅子與螢幕立刻回到原位，不延後。物品狀態由伺服器模擬，隨快照下發，中途加入者拿到完整狀態；最後一人離線時清空狀態。物品之間不互相碰撞，只和固定的牆、家具與玩家碰撞；狗也避開被打飛的物品。接待區固定椅子、沙發、隔板與桌子本身不可射。
- 原因：讓射擊對辦公室物件有可見且持續的結果；被打飛的物品留在場上，會實際影響移動與射線。伺服器權威確保所有人看到同一位置，中途加入者也能拿到正確狀態。椅子在主人上線/離線時必須回原位，否則離線時坐在座位上的人偶會與椅子位置不符。
- 影響：`shared/props.js` 負責物品狀態、衝量與 `stepProps` 純函式；`shared/collision.js` 與 `shared/raycast.js` 以疊加層同時排除原位碰撞盒、加入移動後的碰撞盒；`worker/Room.js` 在 20Hz 計時器中模擬移動中的物品並計時回復；`worker/dog.js` 使用同一疊加層；`shared/protocol.js` 的快照與 welcome 帶出位置、朝向、倒下角度、是否靜止與剩餘回復時間。客戶端 `utils/office/props.js` 依伺服器位置插值、呈現倒下與躺下姿勢及回復時滑回原位的動畫，不做預測；有人坐的椅子不是可瞄準目標，被打飛停在場上的物品仍可被瞄準再射。初速、摩擦、重力、旋轉、倒下角度、碰撞高度與回復動畫等參數放在具名常數，待試玩後微調。再射重新計時若造成困擾，可改為不重新計時。
- 取代：2026-11-14 同日第一版「射完消失」(動畫結束後即隱藏、不留在場上、不擋移動與射線)已被本版物理規則取代。

## 2026-11-15：螢幕放大命中盒，會客室椅子與圓桌可射

- 決策：螢幕的射線判定改用放大的命中盒，各方向放大 0.12 公尺，客戶端瞄準框使用同一尺寸；物理碰撞與顯示不變。螢幕被射後必定落到地板，若在桌上會持續滑到桌邊。會客室三張椅子(`reception-chair-w/e/s`)比照辦公椅可射，回復 20 秒，尺寸較小。會客室圓桌(`round-table`)新增物品種類 `table`：被射後滑 0.2~1 公尺、側躺、30 秒回復；倒下或移動後的盒不可站立，玩家若站在圓桌上被射，會被移到地板。會議室長桌、沙發、書櫃不在可射範圍。
- 原因：螢幕碰撞盒只有 0.03 公尺厚，射線很難瞄中；螢幕被射後可能停在桌上或隔壁桌邊，與「確實飛到地上」的預期不符；會客室是接待區唯一的可互動家具，需要與辦公室物件一致的射擊回饋。
- 影響：`shared/props.js` 負責螢幕放大命中盒常數、螢幕落地、`table` 種類與物理常數；`shared/protocol.js` 接受 `table` 種類；`shared/raycast.js`、`shared/collision.js` 與 `worker/Room.js` 處理命中判定、圓桌不可站立與玩家被移到地板；`utils/office/props.js` 與 `components/office/OfficeScene.vue` 負責螢幕瞄準代理 mesh、會客室椅子與圓桌的登錄、圓桌側躺與回復動畫。
- 取代：2026-11-14 物理版中「接待區固定椅子、沙發、隔板與桌子本身不可射」的規定，改為會客室三張椅子與圓桌可射；辦公桌、沙發、隔板與會議室長桌仍不可射。2026-11-14 物理版中螢幕以目前碰撞盒射線判定的部分，改由放大命中盒取代。
